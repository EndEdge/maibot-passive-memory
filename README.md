# 静默群聊记忆

MaiBot 插件。只处理在插件页面勾选的 QQ 群，按批生成群聊摘要和人物事实，写进 A_Memorix。平时可以继续只在被 @ 或点名时回复。

- 「静默群聊记忆」页面按群名和群号搜索、多选。列表来自 MaiBot 已建立的 QQ 群聊。
- 每个群从勾选保存后的新消息开始处理。没有新文字消息时不会调用模型。每个群独立记录进度，重启后接着处理。取消勾选后停止，重新勾选时从当时的新消息开始。
- 模型输出会先保存，再写入原生记忆。写入失败时会重试已保存的结果，同一批次使用同一个摘要 ID。人物事实按原始消息发言者定位 QQ 账号，使用 MaiBot 自带的证据与画像刷新机制。

## 安装

适配 **MaiBot v1.4.3**，需配套支持插件 WebUI v2 的 Dashboard。此仓库的 Dockerfile 在官方镜像基础上加入一个受插件能力权限约束的写回接口。

在部署机克隆本仓库，从仓库根目录构建：

```sh
docker build -t maibot-passive-memory:1.4.3 .
```

在现有 Compose 中把 **MaiBot 服务**的 `image` 指到 `maibot-passive-memory:1.4.3`，并把本仓库的 `plugin/` 目录放进当前 Bot 的第三方插件目录。多实例部署通常是 `bots/<实例 ID>/plugins/`，以后台「插件扩展」显示的路径和现有挂载为准。可以复制为 `plugins/maibot-passive-memory/`，也可单独绑定该子目录。

镜像内也有一份插件文件，可用 `docker cp <容器名>:/opt/maibot-passive-memory/. <实际插件目录>/maibot-passive-memory/` 提取。保留现有配置、数据和 QQ 适配器挂载，然后用 Compose 重建 MaiBot 服务。若使用不同名称的同版本基础镜像，构建时传入 `--build-arg MAIBOT_BASE=你的镜像:v1.4.3`。

1. 在「插件扩展」启用插件，打开「静默群聊记忆」。
2. 勾选群聊并点「保存选择」。默认每 5 分钟处理一次，插件设置可以调整间隔，留空模型名时使用 MaiBot 的「记忆」分工。
3. 确认 A_Memorix、文本 embedding 与记忆模型可用，目标群未被记忆过滤。让选中的群自然产生一些消息，再到「长期记忆 → 记忆流」按群查看摘要，并在「人物画像」按账号检查有证据的事实。
4. 群聊没有新的可处理文本时，下一轮不会调用生成模型。可在「统计」中按模型任务查看调用变化。

插件运行数据在当前 Bot 的插件数据目录。若配置的是远程记忆模型，选中群的新消息片段会发给该模型服务商。原生画像按人维护，之后的画像使用范围由 MaiBot 自身的配置决定。原生回复触发的摘要机制仍会按宿主原配置运行。

如需停用，在后台关闭插件即可。恢复官方镜像时把 Compose 的镜像切回原版本并移除插件目录。已写入的原生记忆可在长期记忆后台按来源处理。
